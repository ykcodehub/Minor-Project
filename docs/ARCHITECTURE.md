# Architecture decisions and audit

The user explicitly authorized implementation on 8 November 2026. The specifications' older “not yet authorized” and “documents are the current deliverable” notes describe their drafting state and do not override the current request. Functional behavior follows FRD, technical boundaries TRD, visual tokens Design, scope PRD; evidence/privacy restrictions take precedence.

1. **Clean rebuild, modular monolith.** The prior ZIP was inspected without running it or importing historical keys. Its upload handler lacked ownership and durable processing, validated mainly extensions, performed synchronous model calls in request processing, and returned raw exceptions. Frontend format/limit assumptions diverged from backend and results navigation depended on ephemeral state. No old backend code was copied.
2. **React 19 / TypeScript / Vite frontend; FastAPI / SQLAlchemy backend.** Four specification text transcriptions are preserved in docs. PostgreSQL is the runtime and deployment database. SQLite is permitted only in explicit isolated test mode; runtime configuration requires PostgreSQL. No Redis, vector database, Kubernetes or unnecessary container images.
3. **Immutable source instances.** Original bytes are encrypted privately; source IDs identify immutable captured versions. A display name never determines a storage path. Source hash and acquisition metadata are independent of model output. Unicode code-point offsets address unmodified extracted section text; identity source maps and format locators describe extraction. DOCX paragraph locations never masquerade as printed page numbers. PDF preview falls back to extracted blocks with real page/bounding-box metadata; there is no fabricated visual overlay.
4. **Evidence boundaries.** Candidate schemas are strict. Deterministic verification checks source, section, quote, page and offsets. Separate semantic/context review checks interpretation, qualifications and cross-references. Unsupported/ambiguous findings remain inspectable. Whole-source context is bounded; broader context limits withhold supported status. A human-labeled external evaluation remains a release gate.
5. **Durable jobs.** DB-backed jobs are claimed with PostgreSQL SKIP LOCKED plus conditional updates. Lease-token checks prevent canceled/stale workers from persisting. Heartbeats extend bounded leases. Interrupted generation is explicitly failed rather than automatically rebilled. Per-call resume/cost ceilings remain incomplete; the retry UI cannot promise an unbilled retry.
6. **Private storage.** A concrete encrypted filesystem adapter serves development and persistent-volume deployments. Rollback removes uncommitted blobs; committed deletion uses a durable known-object outbox. Unknown blobs are never swept, preserving data from earlier databases. Configured key namespaces prevent overwriting older encrypted content. S3-compatible deployment support remains unimplemented rather than falsely configured. Encryption is not a substitute for restrictive OS permissions or encrypted database backups.
7. **Discovery safety.** URL fetches pin validated public addresses at connection and preserve TLS SNI; validate redirects and prohibit credentials, unusual ports, private/reserved/multicast addresses. Robots, byte/deadline/request limits and same-site restrictions apply. Direct links plus one bounded sitemap are inspected. Dynamic, external, nested-sitemap and signed-in documents are not claimed complete.
8. **Provider portability without hidden routing.** Three HTTP adapters use official structured-output contracts; provider catalog health calls can report model availability. Provider/model/key are deployment configuration. Only the consented allowlist can fall back. Live simple probes succeeded for all three providers and full extraction/review succeeded for Gemini and Groq. OpenRouter full schema returned429. Calibrated reliability, ongoing pricing/free access and human accuracy remain unestablished.
9. **P1 scope.** Source comparison is deterministic retained-text alignment, not semantic conflict detection or monitoring. Optional MCP is read-only and uses a deployment-scoped account credential and the same application authorization. Reviewer adjudication, OCR, trusted timestamping, alerts and legal research remain explicit future work.

Dependencies: authentication/ownership → source storage/extraction → mapped chunks → candidate generation → deterministic match → semantic/context check → findings/passports/Q&A/export. Discovery feeds selected snapshots into ingestion. Frontend depends on these REST contracts; it never supplies owner IDs or provider secrets. REST and MCP reuse authorized services rather than duplicating a second backend.

Maintainer ownership: UI (frontend/), Backend/Security (auth, API, persistence, worker, storage), AI/Evidence (providers and analysis/verification), Discovery/Provenance (ingest/chunking/discovery), QA (tests and verification). Named owners and independent release reviewers remain to be assigned.

Retention is measured from capture, rather than extended silently on each read. This is stricter and predictable; the UI and metadata expose expiry. Relational evidence_spans keep foreign-key links to finding/source/section for valid evidence; rejected model references remain inspectable in immutable candidate payloads. New model calls have UTC timestamps; unrecorded legacy call times remain null.


## Production storage amendment (10 November 2026)

The filesystem-only limitation above is superseded by the private encrypted S3 adapter. Development filesystem data is preserved; production requires S3 and a stable shared key. API and worker run separately from the Vercel static frontend. Remote storage/container/hosting qualification remains open. See DEPLOYMENT.md and the latest VERIFICATION.md.
